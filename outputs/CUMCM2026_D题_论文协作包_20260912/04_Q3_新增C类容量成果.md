# Q3：固定 Q2 排程后的新增 C 类容量

## 1. 题目要求

基于问题 2 的无冲突用频计划，在不增加时频资源、且不限制相对于原计划的平移幅度的
条件下，最多安排多少台 C 类用频装备，并将新增计划写入 `result3.xlsx`。

## 2. 关键依赖

Q3 不是对所有可能 Q2 排程求一个统一常数，而是固定一份完整 Q2 输入后求新增容量。
当前输入为：

- `Q2-T-incumbent-v1.json`；
- `H=643`；
- 频率域 `[0,100)`；
- C 模板：频宽 3、单次持续 2、间隔 8、次数 12；
- Q2 输入包含全部 150 个状态，展开 1,277 个使用窗，冲突数 0。

如果将来 Q2 找到不同的 `M` 或不同平移位置，必须重新运行 Q3；不能把队友分支的
Q3 结果接到本地 T 排程上。

## 3. 候选生成

新增 C 计划由首次频率左端 `f` 与首次时间左端 `s` 确定：

$$
[f,f+3)\times[s+10k,s+10k+2),\qquad k=0,\ldots,11.
$$

完整跨度为

$$
L_C=2+11(2+8)=112.
$$

因此

$$
f\in\{0,\ldots,97\},\qquad s\in\{0,\ldots,531\},
$$

原始候选数为

$$
98\times532=52,136.
$$

## 4. 候选过滤

将冻结 Q2 的 150 个计划完整展开，得到已占资源单元集合 `U_2`。新增候选 `p` 的
占用集合为 `U_p`；若

$$
U_p\cap U_2\ne\varnothing,
$$

则删除该候选。该步骤检查的是 Q2 平移后的完整排程，而不是 Q1 的 297 条原始冲突边。

| 项目 | 数值 |
|---|---:|
| 原始候选 | 52,136 |
| 与 Q2 冲突删除 | 49,684 |
| 兼容候选 | 2,452 |
| 每个候选占用单元 | 72 |

## 5. 最大集合打包模型

对兼容候选定义二元变量 `z_p`。对每个时频资源单元 `(f,t)`，令 `P_ft` 为占用它的
候选集合，加入

$$
\sum_{p\in P_{ft}}z_p\le1.
$$

目标为

$$
\max\sum_p z_p.
$$

由于区间端点为整数且采用半开区间，共享一个整数资源单元与发生正长度交叠等价；
资源单元团模型不会把不同周期窗口错误地当成独立设备。

## 6. 求解与独立复核

- 资源单元 CP-SAT：`OPTIMAL`，目标值 138，best bound 138；
- 同一候选集改写为 89,989 条逐候选冲突边：独立 CP-SAT 同样 `OPTIMAL=138`；
- 合并后的完整排程重新送统一周期检测器：冲突 0、边界违规 0。

## 7. 实际结果

| 指标 | 数值 |
|---|---:|
| 新增 C 类计划 | 138 |
| 编号范围 | C091–C228 |
| 合并后计划数 | 288 |
| 合并后使用窗数 | 2,933 |
| 冲突数 | 0 |
| 边界违规 | 0 |
| 求解状态 | `OPTIMAL` |

当前结果支持的严格表述是：

> 在冻结 `Q2-T-incumbent-v1`、`H=643` 和 C 模板 `(3,2,8,12)` 后，Q3 的新增容量
> 为 138 台，且该候选集合打包模型达到 `OPTIMAL`。

“最多 138 台”不能脱离上述 Q2 输入、时间边界和 C 模板写成无条件结论。
