# CUMCM2026 D 题 Q3：冻结 Q2 排程后的新增 C 类容量

## 1. 输入与边界

Q3 使用冻结的 `Q2-T-incumbent-v1`，而不是继续变化的探索性 Q2 文件。该排程包含
附件 1 的 150 项计划，指标为撤销 6、调整 120，统一周期冲突检测器复验冲突数为 0。

本文采用与 Q2 一致的整数半开资源域

\[
\mathcal R=[0,100)\times[0,643),
\]

其中频率槽数为 100，时间边界 643 由附件 1 全部重复使用窗的最大结束时刻反推。
该时间边界不是题面直接给出的官方常数，因此 Q3 结论必须带上这一建模口径。

附件 1 中 90 个 C 类计划具有同一模板：频宽 3、单次持续 2、间隔 8、使用 12 次。
问题 3 的新增计划沿用这一模板。若以初始频段左端 $f$ 和首次使用时间左端 $s$
表示一个新增计划，则其 12 个使用窗为

\[
 [f,f+3)\times[s+10k,s+10k+2),\qquad k=0,\ldots,11.
\]

一项新增计划的时间跨度为

\[
L_C=2+11(2+8)=112.
\]

因此即使不限制相对于原始计划的平移幅度，仍需满足

\[
f\in\{0,\ldots,97\},\qquad s\in\{0,\ldots,531\}.
\]

若不设置有限时间边界，新增计划可以在时间轴上依次后移，Q3 的“最大数量”将无界；
所以固定规划期是使题目成为有限优化问题的必要条件。

## 2. 候选过滤

先将冻结 Q2 的所有未撤销状态完全展开，得到既有计划占用的整数时频单元集合
\(U_2\)。对每个位置候选 $p=(f,s)$，记其 72 个占用单元为 $U_p$。若

\[
U_p\cap U_2\ne\varnothing,
\]

则候选与 Q2 排程冲突，直接删除。该步骤不是只检查 Q1 的原始冲突边，而是检查
候选与 Q2 平移后的全部最终状态，和 Q2 的全局消解语义一致。

| 项目 | 数值 |
|---|---:|
| 原始位置候选 | $98\times532=52,136$ |
| 与冻结 Q2 冲突而删除 | 49,684 |
| 保留候选 | 2,452 |
| 冻结 Q2 已占整数单元 | 15,630 |

## 3. 最大集合打包模型

对每个保留候选定义二元变量 $z_p$。对于任意整数时频单元 $(f,t)$，令
\(\mathcal P_{f,t}=\{p:(f,t)\in U_p\}\)，加入资源单元约束

\[
\sum_{p\in\mathcal P_{f,t}}z_p\le 1.
\]

目标为

\[
\max \sum_{p\in\mathcal P}z_p.
\]

由于所有区间端点均为整数且采用半开区间，两个候选矩形发生正长度交叠，当且仅当
它们共享至少一个整数时频单元。因此资源单元团约束与逐候选冲突边约束等价，既避免
遗漏新候选之间的冲突，也不需要将每个重复窗误当作独立设备变量。

## 4. 求解与独立复验

使用 CP-SAT 求解上述 0--1 集合打包模型，并以确定性贪心解作为 warm start。求解器
返回 `OPTIMAL`，目标值和 best bound 均为 138，最优性间隙为 0。

作为独立表达复核，将同一批 2,452 个候选改写为 89,989 条逐候选冲突边并重新求解，
仍返回 `OPTIMAL=138`、best bound=138。该复核保留在
`outputs/q3/pairwise_crosscheck.json`，用于排除资源单元团编码的实现性偏差。

将选出的新增计划与冻结 Q2 的 150 项状态合并，再调用统一周期冲突检测器逐窗复验：

| 指标 | 数值 |
|---|---:|
| 新增 C 类计划 | 138 |
| 合并后计划数 | 288 |
| 合并后使用窗数 | 2,933 |
| 全局冲突数 | 0 |
| 边界违规数 | 0 |
| 求解状态 | `OPTIMAL` |

新增计划编号为 `C091` 至 `C228`。例如前两项为 `C091: [0,3), [0,2)`、
`C092: [72,75), [0,2)`；完整清单以 Excel 和 JSON 文件为准。
