# Q2-R41 原型实现说明（baseline：冲突图 GRASP + 局部搜索/ILS）

## 0. 一句话结论
在冻结 seeds=[11,29,47]、每重复 185s 墙钟下，三重复全部得到**零残留冲突可行解**
（evaluator `feasible=true`、`n_violations=0`），标量中位数 **19,009,618,530,491**，
中位重复元组 **(撤销19, 调整96, 优先级损失1853, 幅度491)**；
但撤销数极差 9（19/28/19）⇒ 触发 route 预设的"对种子极端敏感"与"撤销数明显高于精确路线"两条
失败条件 ⇒ **只能作为启发式对照证据**，不可用作质量基准。

## 1. 口径绑定（同 ADJUDICATION.json）
T_MAX=643 资源盒 / 半开区间 / 平移越界即动作无效 / 词典序四级（撤销·调整·Σw·被改·Σ|δ|，
撤销优先级损失 2 倍）/ 单参数或撤销 / 数据取 `data/canonical_plans.csv` 与 evaluator 同列序。
可行性判据在**全势冲突边 G\***（1693 条）上维护：非 G\* 计划对在任意合法动作下都不可能共占，
故"G\* 残留=0" ⇔ evaluator 的 `residual_conflict` 为空；输出前再用掩码全量复核一次。

## 2. 算法（参数在跑实验前冻结，见 `grasp_record_seed*.params`）
```
构造  冲突导向下降贪心：每步采样 4 条残留边 → 端点各取"与对端当前动作相容、按
      (调整,优先级,幅度) 升序的前 8 个动作" → 只保留严格减少残留边的动作
      → 打分 = Δ残留×1e6 + Δ(1e12·撤销 + 1e8·调整 + 1e4·优先级 + 幅度) → RCL(35%) 随机取
      停滞 20 步 ⇒ 撤销该边类别优先级较低的一端（保证终止）
joint 单边无改进动作时的双边逃生（两端同时换动作，topk=3×3）
LS1   去撤销：按撤销代价降序（先救 A/B）逐个计划试代价升序前 12 个动作 + ≤8 步修复，
      元组严格变好才接受 —— 层1 的唯一有效降撤销算子
LS2   缩幅/去调整：换更便宜动作且残留边不增
LS3   负担转移：A/B 被调计划换恒等，冲突由邻居吸收（保护自己端）
ILS/LNS 从当前最优出发：以 0.75 概率"成批去撤销 1-6 个高优先级撤销计划"后重新消解+LS，
      否则随机扰动 2-6 个计划；每起点最多 6 轮 LNS
```

## 4. 关键教训（进方法学/写作层）
1. **撤销层是 GRASP 的天花板**：残留冲突图的"硬边"需要多计划协同重排，单边改进 + ≤8 步修复
   只能把撤销数从 31-33 压到 19-28；而精确路线用整体约束把同一实例压到 6。
   ⇒ 本路线的价值是给出"启发式 vs 精确"的差距量（撤销数差 13，标量差 ~1.30e13）。
2. **打分权重决定成败**：若把"消解边数"权重抬高到接近撤销权重（早期版本 W_RES=1e14），
   贪心会疯狂撤销（首次实现 32-41 个撤销）；把撤销代价严格压在"减少残留"之上
   （W_RES=1e6 ≪ 1e12）后立刻降到 19-28。这正是 CH-04 route 写的"贪心易过早撤销"风险。
3. **层2-4 与层1 反向**：撤销越少 ⇒ 调整越多（19 撤销配 95-96 调整；28 撤销配 75 调整），
   所以只看 `adjusted` 会选错方案 —— 词典序口径必须写死。
4. **增量评估正确性**：每步动作后用掩码全量复核（`internal_residual_full_mask`）与 G\* 位掩码
   增量结果一致（三重复全 0）；开发期曾因"边 key 方向(0/1 位置)"写反导致 IndexError，
   已修并在 DEV_LOG.md 登记。
